## 2. Как устроено приложение

Один HTML-файл + файл данных. Код не знает про конкретную неделю: он отрисовывает то, что лежит в `weeks.json`.

**Вкладки:** ✏️ Spelling · 📖 Reading · 🔢 Maths · 📄 Report.

- **Spelling**: 1 Look & listen (слова с подсветкой суффикса, озвучка) → 2 Practise (слышит — печатает — проверка по буквам) → 3 Friday test (все слова вразнобой, счёт, лучший результат).
- **Reading**: 1 Read the text (страницы с текстом из оригинального листа + «🔊 Read it to me» / «🎤 I'll read it» по текстовому слою или OCR на устройстве) → 2 Questions (сверху страница листа с вопросами, ниже ВСЕ вопросы листа по порядку: 1–5 с вариантами ответа + Bonus, 6–9 — поле для пера + поле для печати). Отдельных вкладок Quiz / My answers больше нет.
- **✏️ Write on this page** — на каждой показанной странице листа (Read, Questions, разделы Maths) кнопка включает рисование пером прямо поверх страницы (пока выключена — страница листается пальцем). Штрихи хранятся как обычный ink: `spag-ink-<weekId>-pg<R|M><стр>`. В отчёт исписанная страница попадает картинкой (страница + почерк) в своём разделе, после фото; считается выполнением («done on paper (written on the sheet)»). CSS: `.page-ink` исключён из правил фиксированной высоты `.ink-canvas` — не ломать.
- **📷 Done on paper?** — в каждом разделе (Spelling, Reading Questions, Times tables, Column sums, Problems) есть блок для фото выполненного на бумаге задания (камера или Photos; несколько фото; хранятся в IndexedDB устройства, ключ `photos-<weekId>-<sec>`, сжатие до 1600px JPEG). В отчёте фото идут первыми в своём разделе; если задание сделано ещё и в приложении — ниже добавляется «Also done in the app» с ответами. Если в разделе только фото, списка «(not answered)» нет. Любой из вариантов считается выполнением (строка Results: «done on paper (photo attached)» / «… + done on paper»).
- **Maths**: над каждым разделом (Times tables / Column sums / Problems) показывается соответствующая страница оригинального листа; полная галерея листа при этом скрыта. Какие страницы куда — задаёт `sheetMap` недели.
- **Maths**: 1 Times tables (быстрые примеры, таймер, Check all) → 2 Column sums (столбик впечатан в клетки, ребёнок пишет под чертой, ответ + проверка обратным действием) → 3 Problems (задачи: клетчатое поле, «штампы» чисел из условия, числовые/оценочные/текстовые части).
- **Report**: строка «что записано на этом устройстве», имя, две карточки — SPAG report и Maths report, каждая: Make the PDF → 📤 Send (системное «Поделиться») / 💾 Save (в «Файлы → Загрузки»).

**Поле для пера** (`makeInk`): карандаш / 🔵 🔴 ⚫ / ластик / отмена / Clear. Клетки в математике, линейки в чтении. Размер клетки подстраивается под ширину экрана. Штрихи хранятся в относительных координатах (0..1) — не ломаются при смене размера.

**Где хранятся результаты:** только в `localStorage` того браузера/иконки, где ребёнок работал. Ключи `spag-res-<weekId>`, `spag-best-<weekId>`, `spag-ink-<weekId>-…`, `spag-name`, `spag-pen`, `spag-voice`. На сервер ничего не уходит. ⚠️ Safari, иконка на экране «Домой» и версия в Claude — три разных хранилища: решать и делать PDF нужно в одном и том же месте.

**Образцы ответов** спрятаны за родительским кодом: значок 🔒 вверху → код `2026` → появляются кнопки «💡 Show a good answer». Действует до закрытия приложения.

**Голос:** встроенный TTS iOS; лучший — Daniel (Enhanced) или Serena (Premium), English (UK), скачать в Настройки → Универсальный доступ → Устный контент → Голоса. Выбор в меню вверху приложения.

## 4. Как добавить новую неделю (инструкция для Claude)

### 4.1. Входные данные
Два PDF из ManageBac. Прочитать **все страницы как изображения** (`pdftoppm` → Read), а не только текст: сетки с цифрами и картинки текстом не извлекаются.

### 4.2. Структура записи недели (`weeks.json` — массив таких объектов)

```json
{
  "id": "week7",            // уникальный, латиница, без пробелов; НЕ менять у существующих недель (к нему привязаны результаты на iPad)
  "title": "Week 7",
  "order": 7,               // число для сортировки; последняя по order открывается по умолчанию
  "pattern": { "title": "Words ending in -tion", "tip": "1–2 предложения о правиле для ребёнка", "suffix": "tion" },  // suffix "" если общего окончания нет
  "words": ["…"],           // ВСЕ слова списка, lowercase, точно как в листе
  "sentences": { "word": "короткое естественное предложение" },  // для КАЖДОГО слова — используется озвучкой
  "reading": {
    "title": "название текста",
    "passages": [ { "pic": "🐨", "title": "заголовок", "text": "ПЕРЕСКАЗ своими словами, 2–4 предложения, все факты/числа/имена сохранить" } ],
    "glossary": [ ["word", "простое определение"] ]
  },
  "quiz": [ { "q": "вопрос", "a": ["ПРАВИЛЬНЫЙ ПЕРВЫМ", "неверный", "неверный", "неверный"] } ],   // 10–12
  "open": [ { "q": "открытый вопрос", "starters": "начало 1 / начало 2", "model": "образцовый ответ 2–3 предложения" } ],
  "maths": {
    "title": "Maths Group 8 · Week 7", "unit": "тема", "intro": "2–3 предложения для ребёнка",
    "timesTables": [ { "q": "7 × 8", "a": 56 }, { "q": "9 × ☐ = 81", "a": 9 } ],   // ☐ для пропущенного числа; только × ÷ (и +−, если есть устный счёт)
    "sums": [ [7834, "+", 3621], [4693, "-", 3142], [23, "×", 4], [96, "÷", 8] ],   // op: "+", "-", "×", "÷"; столбик впечатывается только для + и −
    "problems": [ { "pic": "📚", "title": "…", "text": "условие полностью, числа как в листе", "parts": [
        { "q": "a) …", "type": "number",   "answer": 4253 },
        { "q": "estimated answer", "type": "estimate", "answer": 6319, "hint": "Round first" },   // принимается округлённое в пределах ±6 % / ±150
        { "q": "…", "type": "exact", "answer": ["0.75", ".75"] },   // нечисловые ответы: дроби, время, единицы — все допустимые написания
        { "q": "Explain…", "type": "text", "model": "образцовый ответ" }   // пером или текстом; проверки нет
    ] } ]
  }
}
```

Правила содержимого:
- **Вопросы листа воспроизводить точно**: те же формулировки, порядок и нумерация («1.», «2.»…). «Соедини пары» → по одному вопросу на пару с теми же вариантами; «вставь слово» → вопрос с пропуском. Свои вопросы — только после, с пометкой «Bonus:». Открытые вопросы (`open`) — с номерами листа в начале `q`.
- **Текст для чтения — только пересказ.** Листы школы — материалы Twinkl (авторское право); дословно не копировать. Факты, числа, имена — сохранить точно.
- **Ответы считать и перепроверять** (скриптом, не в уме). Один неверный `answer` = ребёнок получит «✗» за правильное решение.
- Всё, что не укладывается в типы (нарисовать фигуру, заполнить таблицу, график), оформлять как `problems` с частями `type: "text"` — ребёнок решает пером, автопроверки нет.
- Английские тексты для ребёнка 9–10 лет, UK spelling.
- Эмодзи `pic` — один символ.

### 4.2a. Обязательный отчёт Денису после сборки недели
После каждой новой недели (и любой правки заданий) писать в чат отдельным блоком **«Что отличается от листа»**: какие вопросы переформулированы, какие добавлены (Bonus), чего нет в приложении (например, рисование), что пересказано. Если отличий нет — так и написать. Без этого блока неделя не считается готовой: родитель должен знать, что именно уйдёт учителю.

### 4.2a-bis. Типы заданий по математике, которые умеет приложение
- `timesTables`: `{q, a}`; `☐` в `q` = пропущенное число.
- `sums`: `[a, op, b]` — ребёнок считает сам; **или** `{a, op, b, given}` — на листе уже написан ответ `given`, ребёнок проверяет обратным действием и жмёт «Correct / Incorrect», затем вписывает верный ответ (Term 1B Week 1, стр. 2).
- `problems[].parts[]`: `type: number` (точное число), `estimate` (округлённая оценка), `exact` (строка/список допустимых строк — для денег и т.п.), `text` (свободный ответ + `model`). Если `title` начинается с цифры или ★ — нумерация листа сохраняется, приложение своей не добавляет.

### 4.2b. Оригинальный лист в приложении
Текст листа в приложение не перепечатывается (авторское право — материалы Twinkl и т.п.); вопросы — дословно с листа (см. 4.2a). Лист показывается картинками: на Cloudflare-сайте приложение само скачивает PDF из `W.sheets` при первом открытии, иначе родитель прикрепляет PDF/фото через «📎 Attach the sheet». Страницы (картинка + текстовый слой/OCR) хранятся в IndexedDB устройства (`spag-sheets`, ключ `sheet-<weekId>-R|M`).

У недели обязательно поле `sheetMap` — номера страниц PDF (с 1) для каждого раздела:
```json
"sheetMap": { "R": { "text": [2, 3], "questions": [4] }, "M": { "tt": [1], "sums": [3], "problems": [2, 4] } }
```
Read показывает только `R.text`, вкладка Questions — `R.questions`, разделы Maths — свои страницы. Для новой недели номера определять по PDF (`pdftoppm` и посмотреть). Та же неделя в Claude-версии: `sheetMap` пишется в документ `weeks/<id>` через `ArtifactData`.

## 5. Как менять код приложения без поломок

### 5.1. Два файла — одна логика
`site/index.html` (сайт) и `/home/claude/spag-week6.html` (версия в Claude) содержат один и тот же код, кроме:
- сайт: нет блока «For grown-ups», нет `claude.use(...)`, недели берутся `fetch('weeks.json')`, PDF через `navigator.share` / `<a download>`;
- Claude-версия: `capabilities` (db, user, sample с images, downloads, assets), проверка почерка через `sample.json`, «Send» через `assets.upload` + коллекция `reports`.

Любую правку вносить **в оба файла** одним скриптом (как делалось в сессии: python с `assert old in s` для каждой замены — если строка не нашлась, скрипт падает, и правка не применяется наполовину).

### 5.2. Обязательная проверка перед публикацией
1. `node --check` на извлечённом `<script>` — синтаксис.
2. Локальный сервер `python3 -m http.server 8123` в `site/` + Playwright-прогон (`/tmp/.../scratchpad/e2e.js` в сессии; если потерян — написать заново по этому списку):
   - weekLabel = последняя неделя; 10 плиток слов;
   - Practise: ввод правильного слова → «✓ Correct»;
   - Friday test: 10/10 при правильных ответах; сохранился `spag-best-…`;
   - Quiz: 10/10; Reading check: процент и список слов;
   - Maths: Check all = N/N; sum + inverse; estimate; word problem;
   - штрих пером → `hasInk()` true после reload;
   - Report: обе карточки → «Ready: … .pdf»; **собрать PDF из вкладки Report, когда Maths скрыта** (именно так ловился баг с пустыми картинками);
   - `scrollWidth` = ширине окна при 393 px и 1366 px; консоль без ошибок.
3. Сгенерированный Maths PDF открыть `pdftotext`/`pdfimages`: должны быть ответы, изображения, имя латиницей.

### 5.3. Известные ловушки (уже наступали)
| Ловушка | Что делать |
|---|---|
| Перезапись `className` стирает служебные классы (`.v`, `.rv`) | Всегда `'verdict v ' + …`, не `'verdict ' + …` |
| Скрытый `canvas` имеет размер 0×0 → экспорт картинки в PDF падает | `toImage()` использует `lastRect`; никогда не брать размер только из `getBoundingClientRect()` |
| Шрифт jsPDF не знает кириллицу и символы − × ÷ ☐ — « ?? » | Весь текст через `pdfSafe()` (транслитерация + замены) |
| Напечатанный ответ без обработчика `change` не сохраняется | У каждого `input/textarea` ответа — сохранение в `results()` |
| `sed` с `v.className` заодно меняет `rv.className` | Правки через python с точными строками и `assert` |
| GitHub Pages несколько минут отдаёт смесь старых и новых файлов | После push ждать 1–2 мин; `weeks.json` запрашивается с `?v=Date.now()` |
| Результаты «пропали» | Проверить, в той же ли «двери» открыто приложение (Safari / иконка / Claude); строка «Recorded in this app…» во вкладке Report |
| Firefox/Chrome в тесте не поддерживают `navigator.share` | Это нормально; на iOS работает |
| Экранное время iOS «Только разрешённые сайты» блокирует cdnjs/fonts → приложение ломается | Не использовать этот режим |
| Патч-скрипт с заменой «от строки A до строки B» захватил лишний блок (пропали `results()`, `saveResults()`, весь INK CANVAS) | Заменять только точные фрагменты; после патча сверять список функций с `git show HEAD:index.html` (`grep -o "^function [a-zA-Z]*"`) и прогонять тесты |
| Обработчик «📎 Attach» вызывал `render()`, а не обёртку → страницы над разделами не появлялись | `mountSheetPages(subj)` вызывается внутри `render()` |

### 5.4. Что НЕ менять без необходимости
- `id` существующих недель и ключи `localStorage` — иначе ребёнок потеряет результаты.
- Формат `strokes` (массив `{p:[[x,y]…], e, c}` и штампы `{t:'s', s, x, y, cell, c}`) — сохранённые рисунки должны читаться новым кодом.
- Внешние библиотеки: только `jspdf 2.5.1` с cdnjs (на сайте) — других зависимостей нет и не нужно.
